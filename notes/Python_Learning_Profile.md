# Python 学习画像档案

这份文件用于保存当前阶段对学习者 Python 掌握程度和技能水平的判断。它不是一次性的评语，而是可持续维护的学习档案：每完成一个小阶段、阶段测验、代码审查或阶段项目后，都可以在这里更新“当前能力快照”和“历史评估记录”。

维护原则：

1. 画像判断必须基于可观察证据，例如阶段测验、批改记录、代码审查、练习脚本、笔记质量和追问表现。
2. 评价要区分“已经稳定掌握”“基本理解但表达需精修”“尚未系统学习”“容易混淆的边界”。
3. 不把分数当作唯一依据；更重视解释能力、迁移能力、工程意识和能否主动发现边界。
4. 每次更新时保留历史记录，不直接抹掉旧判断；如果旧判断过时，应追加新的修正说明。

- 能把源码字面量、对象本体、显示形式、`repr()`、`str()`、`print()`、交互式回显区分开。

- 要继续警惕 `print(...)` 的输出效果和 `print(...)` 的返回值不是一回事。

- 进入列表和元组后，需要重点压实可变对象共享引用、浅拷贝、深拷贝、原地修改、方法返回值和嵌套容器陷阱。

## 4. 高频误区观察表

| 高频误区 | 当前状态 | 修正规则 |
| --- | --- | --- |
| 把“值相等”说成“同一个对象” | 已多次被指出，需要持续压实 | 普通值比较说“相等”；只有身份比较才说“同一个对象” |
| 把 `print()` 的输出当成 `print()` 的返回值 | 已纠正，但要继续警惕 | `print()` 把文本写到输出流，并返回 `None` |
| 把显示形式当成对象本体 | 已建立模型，但容器和 `bytes` 场景仍需提醒 | `repr()`、容器显示、交互式回显都是显示层，不等于对象内部内容 |
| 把 `bytes` 的 `repr` 显示当作真实字节内容 | 已在字符串测验中暴露 | `b'\\n'` 中的可见反斜杠可能只是显示转义，真实字节要看数值 |
| 过度依赖 CPython 实现细节 | 已有提醒 | 小整数缓存、字符串驻留、完整切片返回自身等不要作为语言语义依赖 |
| 把“不可变”理解得过粗 | 待在元组阶段强化 | 元组自身不可变，不等于其引用的可变元素不能被修改 |
| 把赋值理解成复制对象 | 待在列表阶段强化 | `a = b` 绑定同一个对象，不会复制容器 |

## 5. 下一阶段学习画像关注点：列表和元组

进入列表和元组阶段后，能力判断需要重点观察以下问题：

1. 是否能稳定区分“修改列表对象”和“让名字绑定到新列表对象”。
2. 是否知道哪些列表操作原地修改，哪些操作创建新对象。
3. 是否能解释列表方法为什么多数返回 `None`。
4. 是否能用 `id()` 观察共享引用，但不在业务逻辑中依赖 `id()`。
5. 是否能解释浅拷贝只复制外层容器，内层可变对象仍可能共享。
6. 是否能发现和解释嵌套列表重复引用陷阱。
7. 是否能解释元组由逗号创建，而不只是由圆括号创建。
8. 是否能解释单元素元组 `(x,)` 和普通括号表达式 `(x)` 的区别。
9. 是否能解释元组不可变性的边界：不能替换元素引用，但元素对象本身若可变，仍可能原地变化。
10. 是否能在工程中合理选择列表和元组：可变记录集合优先列表；固定结构、函数多返回值、不可随意改动的记录可考虑元组。
