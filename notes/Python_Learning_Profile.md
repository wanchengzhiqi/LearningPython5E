# Python 学习画像档案

这份文件用于保存当前阶段对学习者 Python 掌握程度和技能水平的判断。它不是一次性的评语，而是可持续维护的学习档案：每完成一个小阶段、阶段测验、代码审查或阶段项目后，都可以在这里更新“当前能力快照”和“历史评估记录”。

维护原则：

1. 画像判断必须基于可观察证据，例如阶段测验、批改记录、代码审查、练习脚本、笔记质量和追问表现。
2. 评价要区分“已经稳定掌握”“基本理解但表达需精修”“尚未系统学习”“容易混淆的边界”。
3. 不把分数当作唯一依据；更重视解释能力、迁移能力、工程意识和能否主动发现边界。
4. 每次更新时保留历史记录，不直接抹掉旧判断；如果旧判断过时，应追加新的修正说明。

## 4. 高频误区观察表

| 高频误区 | 当前状态 | 修正规则 |
| --- | --- | --- |
| 把“值相等”说成“同一个对象” | 已多次被指出，需要持续压实 | 普通值比较说“相等”；只有身份比较才说“同一个对象” |
| 把 `print()` 的输出当成 `print()` 的返回值 | C11 测验已稳定掌握 | `print()` 把文本写到指定输出流，并返回 `None`；后续继续迁移到日志和外部 I/O |
| 把显示形式当成对象本体 | 已建立模型，但容器和 `bytes` 场景仍需提醒 | `repr()`、容器显示、交互式回显都是显示层，不等于对象内部内容 |
| 把 `bytes` 的 `repr` 显示当作真实字节内容 | 已在字符串测验中暴露 | `b'\\n'` 中的可见反斜杠可能只是显示转义，真实字节要看数值 |
| 过度依赖 CPython 实现细节 | 已有提醒 | 小整数缓存、字符串驻留、完整切片返回自身等不要作为语言语义依赖 |
| 把“不可变”理解得过粗 | 已在元组阶段明显改善，但术语仍需精修 | 元组槽位引用不可替换；如果槽位引用可变对象，那个对象本身仍可原地修改 |
| 把赋值理解成复制对象 | 已明显改善 | `a = b` 绑定同一个对象，不会复制容器；需要复制时要显式使用切片、构造器、`copy.copy()` 或 `copy.deepcopy()` |
| 把“新对象”误说成“深拷贝” | 列表和元组测验中暴露 | `_replace()`、拼接、`sorted()` 等会创建新外层对象，但不等于深拷贝内部所有引用 |
| 忽略命令行选项改变控制流 | 列表和元组测验中暴露 | 先看早返回分支，例如 `--report-json` 会让函数提前返回，不再执行普通展示逻辑 |
| 把 `namedtuple._asdict()` 误认为非普通 `dict` | 阶段测验中已纠正 | Python 3.9 中 `_asdict()` 返回普通 `dict`；旧版本资料可能提到 `OrderedDict`，需按当前版本判断 |
| 把 `ensure_ascii=False` 说成只影响显示形式 | 阶段测验中已纠正 | 它不改变 `json.dumps()` 返回类型，返回值仍是 `str`；但会改变这个 `str` 的实际内容 |
| 混淆 Python 默认字符串编码和文件默认编码 | 已通过本机实验和测验压实 | `sys.getdefaultencoding()` 不是 `open()` 默认文件编码；文本文件读写应显式传入 `encoding` |
| 误判 JSON 对 tuple 的处理 | 阶段测验中已纠正 | `tuple` 通常会被编码成 JSON array，但 JSON 往返后会变成 `list`，不保留 tuple 语义 |
| 把 JSON 说成能恢复多数 Python 类型 | 新增关注点 | JSON 只能保留 JSON 数据模型支持的结构；tuple、set、自定义对象、非字符串 key 等都需要转换或会丢失语义 |
| 把结构化报告最终类型简单说成 `str` | C15 再次精修 | 先有内部 `dict/list` 报告模型，再有 `json.dumps()` 返回但不自动展示的 JSON 文本 `str`，显式输出或写入后才产生对应外部效果 |
| 把文档字符串当作普通表达式副作用 | C10 测验中已暴露并纠正 | 文档字符串是特殊位置上的字符串字面量，被作为 `__doc__` 元数据处理 |
| 把语句执行效果说成语句返回值 | C11 测验已稳定掌握 | 表达式有值；语句组织动作。赋值语句处理目标，不能把执行效果说成普通返回值 |
| 把更换循环变量名当作获得推导式作用域 | C14 测验新增的轻微精度点 | 普通 `for` 不创建块级作用域；换名只能避免覆盖某个特定外层名字，新循环变量仍会残留 |
| 把中途停止的迭代器一概说成已经耗尽 | C14 测验新增的轻微精度点 | 分清正常耗尽、短路或 `break` 后部分消费、尾部仍可继续，以及迭代器已不可达但源容器仍可重遍历 |
| 把运行期内省当成静态安全读取 | C15 测验新增的精修点 | `help()`、`pydoc`、`inspect.signature()` 等可能触发对象属性协议；普通子进程也不是权限沙箱 |
| 把临时目录实验称为严格只读 | C15 测验新增的精修点 | 创建和清理临时目录都是真实写入；严格只读应使用不创建的合成路径或纯内存 helper，需要工作区时应显式改称受控写入 |
| 把哈希一致说成绝对字节同一证明 | C15 测验新增的精修点 | 哈希相等是极强证据但存在理论碰撞，也只覆盖采样结果；直接字节比较仍不能排除采样间修改、并发写入和 TOCTOU |
| 把 `StringIO` 的内容/位置语义外推到所有输出对象 | C16 测验新增的轻微精修点 | 通用合同只承诺按输出协议发起写入；是否可回读、可定位、刷新或持久化由具体对象决定 |
| 把字符串处理结果无条件说成全新身份 | C16 测验新增的非扣分提醒 | 稳定语义是返回结果字符串且不修改原字符串；除非合同明确承诺，不依赖结果与输入的身份关系 |
| 把赋值语句开始执行写成左侧绑定已经完成或整条语句完全未执行 | C17 测验新增的轻微精修点 | 先求值右侧，再处理左侧绑定；右侧异常表示语句已进入，但目标绑定未完成 |
| 机械地把 LEGB 四个字母写成每段代码都实际存在的四层 | C17 测验新增的轻微精修点 | 按词法嵌套画真实路径；没有外层函数时不存在 E 层，直接从 L 进入 G |
| 把函数内创建并返回对象说成对象已经绑定给函数局部名字 | C17 测验新增的轻微精修点 | 对象可在 `return` 表达式中创建并直接交给调用者；只有实际赋值目标才建立名字绑定 |
