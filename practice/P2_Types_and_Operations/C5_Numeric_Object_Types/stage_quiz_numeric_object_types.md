### E3. `& ~MASK` 和 `^ MASK` 的区别（4 分）

解释为什么“删除权限”通常写作：

```python
flags &= ~WRITE
```

而不是：

```python
flags ^= WRITE
```

两者什么时候会得到相同结果？

答题区：

```text
当原子权限（ `READ`、`WRITE`、`EXECUTE` ）的设置保证“至多一个二进制位是1”时，`flags &= ~WRITE` 用于“删除权限”，而 `flags ^= WRITE` 用于“切换权限”，这是因为：“删除权限”的语义是“无论标识是否存在此权限都执行删除操作（保证了绝对删除）”；而“切换权限”的语义是“有则删，无则加”，所以，若标识确实含有对应权限，二者效果一致，可是当标识本没有对应权限时，后者反而会添加该权限，这就和“删除”的意义相悖了。
```

### E4. 固定 8 位视角和 Python 无限精度整数（5 分）

解释下面表达式的含义。`11110001` 在无符号 8 位和有符号 8 位补码视角下分别可以解释成什么？

```python
x = 14
print(~x)
print(f"{(~x) & 0xff:08b}")
```

答题区：

```text
`~x` 意思是：对变量x指向的整数对象14执行“按位取反”操作，Python的整数是无限精度且没有大小限制的（理论上只有物理内存限制），因此，Python保证了：对于任意整数x，等式 `~x == -x - 1` 恒成立。`~x` 返回的结果是整数-15，其二进制表示的低八位就是 `11110001`
`f"{(~x) & 0xff:08b}"` 意思是：将`~x` 返回的结果（即-15）和 `0xff` 作位“与”运算，再把运算结果（仍旧是个整数）的字符串表示形式作格式化处理（以八位二进制格式显示），最终得到一个长度为8的字符串对象（"11110001"）。这类操作通常用于模拟固定8位整数的取反操作
对于 `11110001`，在无符号 8 位和有符号 8 位补码视角下分别解释成正整数241和负整数-15，Python的负整数在位运算场景下通常拥有无限个前导1，而-15的二进制表示的低八位正是 `11110001`
```
