### A2. 换行与反斜杠 n（6 分）



### A3. 原始字符串的边界（5 分）

解释为什么第一行合法，第二行不合法。再写出一种合法表达“以反斜杠结尾的路径字符串”的方式。

```python
r"C:\new\name"
r"C:\new\name\"
```

答题区：

```text
`r"C:\new\name"`返回一个内容为C:\new\name（这里的反斜杠没有转义语义，只是普通字符）的字符串对象，因为它是一个创建原始字符串对象的字面量表达式，源码中最前面的 r 使得反斜杠不再进行转义操作，意即源码中的反斜杠只是一个普通的字符。
字符串细节解释：创建原始字符串对象的字面量表达式源码中写了字符r以及紧跟着的十一个被一对双引号囊括的Unicode字符；对象里实际有C : \ n e w \ n a m e；长度是11；repr()将其显示为 'C:\\new\\name'；print()输出 C:\new\name；经UTF-8编码后是 b'C:\new\name'（字符串内容都属于可打印的ASCII字符，字节序列不会转义）
`r"C:\new\name\"`的执行将触发语法报错，因为它是一个非法的创建原始字符串对象的字面量表达式，源码中最靠后的反斜杠将影响字符串结束语法标识（在当前场景下需要一个双引号）的解析：即便此时的反斜杠不再拥有转义语义，也不代表紧跟其后的双引号不是字符串内容！而Python通常而言是“不允许出现模糊判断的”，因此，这样的源码表示将被视为一种错误表达。
若想合法表达“以反斜杠结尾的路径字符串”，可以这样写源码：`"C:\\new\\name\\"`，当然，也可以这样写：`r"C:\new\name\\"`，不过二者返回的对象并不相等，前者的print输出是 C:\new\name\，而后者的是 C:\new\name\\

“验证前预测”：
执行：
print(r"C:\new\name")
输出：
C:\new\name
交互式环境下再执行：
r"C:\new\name\"
输出：
SyntaxError
再执行：
print("C:\\new\\name\\")
输出：
C:\new\name\
“验证后修正”：
预测正确，无须修正。
```

### B4. 列表显示与元素本体（7 分）

先预测下面代码的输出，再解释为什么 `items[1]` 的长度不是 2。

```python
s = "A\nB"
items = [ch for ch in s]
debug_items = [repr(ch) for ch in s]

print(items)
print(debug_items)
print(len(items[1]))
print(len(debug_items[1]))
print(repr(items[1]))
print(repr(debug_items[1]))
```

答题区：

```text
首先，s绑定到了一个内容为A 换行符 B的长度为3的字符串对象上，表达式 `"A\nB"` 返回一个内容为A 换行符 B的字符串对象，因为它是一个创建字符串对象的字面量表达式，源码中的 \n 代表转义字符（换行符）且长度为1。对于这个字符串的细节解释：创建字符串对象的字面量表达式源码中写了四个被一对双引号囊括的Unicode字符(A、\、n、B)；对象里实际有A 换行符 B；长度是3；repr()将其显示为 'A\nB'；print()输出两行且每行分别显示A与B；经UTF-8编码后是 b'A\nB'（字符串内容中的字符A和B都属于可打印的ASCII字符，字节序列不会转义，但是换行符属于不可打印字符，字节序列会转义）
其次，items绑定到了一个由列表推导式返回的列表对象上，这里的列表推导的意思是：将s绑定的字符串对象的元素逐个取出并按序一一追加至结果列表内，最终的效果等价于 `list(s)`。需要注意的是：列表（或者是容器类型对象）对其内部元素的显示会做额外的repr“显示处理”，类似于交互式回显，但对象的显示只是一种表达方式，它并不会影响对象本身。
最后，debug_items也是绑定到了一个由列表推导式返回的列表对象上，但这里的列表推导的意思是：将s绑定的字符串对象的元素逐个取出，并逐一经过repr调用处理后，按顺序将各个处理结果追加至结果列表内。也就是说，这里的结果列表中的元素本体都已经经历过一次repr处理，若将列表打印出来，这些元素的显示将会是二次repr处理后的样子。
综上，对于下列代码输出结果的预测是：
print(items)  # 输出结果 ['A', '\n', 'B']，输出结果的类型 list
print(debug_items)  # 输出结果 ["'A'", "'\\n'", "'B'"]，输出结果的类型 list
print(len(items[1]))  # 输出结果 1，输出结果的类型 int
print(len(debug_items[1]))  # 输出结果 4，输出结果的类型 int
print(repr(items[1]))  # 输出结果 '\n'，输出结果的类型 str
print(repr(debug_items[1]))  # 输出结果 "'\\n'"，输出结果的类型 str
关于 `print(len(items[1]))` 输出的结果并不是2，正如前面所述，列表对其内部元素的显示会做额外的repr“显示处理”，但元素对象本身不会做任何其他的处理，因此 `items[1]` 返回的实际上正是 `s[1]` 所返回的换行符这个字符串对象，它的长度自然是1

“验证前预测”：
如上所述。
“验证后修正”：
预测正确，无须修正。
```

### 附加挑战题（不计分，已审批）

大部分推理正确，但有两个重要修正点。

第一，`bytes` 显示写错了。正确结果是：

```python
b = "A\n中\\B".encode("utf-8")
print(b)
```

输出：

```python
b'A\n\xe4\xb8\xad\\B'
```

不是：

```python
b'A\n\xe4\xb8\xad\B'
```

原因：字符串里的真实反斜杠字符编码后是字节 `92`，在 `bytes` 的 `repr` 中要显示成 `\\`，避免和转义序列混淆。

第二，关于“对象层/显示层”的标注需要再细一点：

```text
表达式求值发生在对象层；
print 把对象的文本表示写到输出流，是输出显示行为；
列表对象的创建在对象层，列表被 print 时会用元素的 repr 组成显示形式。
```

所以 `print([ch for ch in s])` 不能简单说“这一步发生在显示层”。更准确是：列表推导先创建真实列表对象，`print` 再触发列表显示逻辑。
